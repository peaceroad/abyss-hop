# 深海潜行 - Abyss Hop 実装メモ

## 1. 文書の対象

このメモは、現在の `abyss-hop-optimized.html` の実装内容を確認したうえで、ゲーム全体の構造・ルール・内部処理をまとめたものです。
リポジトリへ配置する際の想定ファイル名は `abyss-hop.html` です。

- 実装形式: HTML / CSS / JavaScriptを1ファイルにまとめた単一HTML
- 外部JavaScriptライブラリ: なし
- 外部画像: なし
- ゲーム本体の外部フォント: なし
- 描画方式: HTML Canvas 2D
- UI言語: 日本語
- 論理解像度: 800 × 600
- 表示比率: 4:3固定
- 永続化: `localStorage`
- JavaScript構成: IIFE（即時実行関数）＋ strict mode

ブラウザでHTMLファイルを直接開くだけで動作し、ビルド工程やWebサーバーを必要としません。

## 2. ゲームの目的と基本ルール

プレイヤーは `🐟` を操作し、海流面を足場として使いながら、できるだけ深く潜り続けます。
カメラは自動で下方向へ進み、画面右上に到達深度を `scroll` 単位で表示します。

深度表示は次の計算です。

```js
const depth = Math.floor(maxScroll / CFG.scrollUnit);
```

現在の `CFG.scrollUnit` は120です。

ゲームオーバーになる条件:

1. `🐟` が敵または `🐚` に接触する
2. `🐟` が画面上端より `cameraMarginTop` 以上流される
3. `🐟` が画面下端より `cameraMarginBottom` 以上落下する

画面上側へ隠れた場合は即終了せず、`topDanger` による猶予があります。
猶予中は上端の暗いグラデーション、泡、「上へ流されている」の警告を表示します。

## 3. 操作方法

| キー | 操作 |
|---|---|
| `B` / `←` | 左へ移動 |
| `F` / `→` | 右へ移動 |
| `P` / `↑` | 接地中にホップ |
| `N` / `↓` | 下方向へダイブ。接地中のダイブに加え、空中でも1回使用可能 |
| `Enter` | タイトルから開始 / ゲームオーバー後に再スタート |
| `R` | ゲームオーバー後に再スタート |
| `Space` | 一時停止中に再開 |
| `Esc` | プレイ中は一時停止 / 一時停止中・ゲームオーバー中はタイトルへ戻る |
| `/` または `?` に相当する物理キー | ヘルプ表示フラグを切り替える |
| `Shift` + `3` | タイトル画面でベスト深度をリセット |

`P` と `N` はキーの押下エッジで処理します。
`e.repeat` と `latched.p` / `latched.n` を使い、長押しによる連続発動を防いでいます。

### フォーカスの実際の挙動

キーボードイベントは `window` に登録されており、入力処理そのものを「Canvasがフォーカス中だけ」に限定する判定はありません。
一方、Canvasまたはウィンドウがフォーカスを失うと、次の処理を行います。

- 押下中キーをクリア
- ホップ・ダイブのラッチを解除
- プレイ中なら `paused` へ移行
- フォーカス取得を促す表示を出す

クリックはCanvasへフォーカスを当てるために使い、クリックだけではゲーム開始・再開を行いません。

### ヘルプ表示に関する現状

ゲーム開始時に `helpTimer = 20` が設定され、ヘルプは最大20秒間表示されます。
`/`・`?` キーは `helpVisible` を切り替えますが、現在の実装では `helpTimer` を復元しません。
そのため、20秒経過後はキーを押してもヘルプを再表示できません。
これは現在のコードどおりの挙動です。

## 4. 画面サイズと座標系

ゲームロジックは常に800 × 600の論理座標で処理します。
表示領域はCSSで4:3を維持しながらビューポートへ最大フィットします。

```css
width: min(100vw, calc(100dvh * 4 / 3));
height: min(100dvh, calc(100vw * 3 / 4));
aspect-ratio: 4 / 3;
```

Canvasの内部バッファは表示サイズとDPRから算出します。
DPRは最大2に制限し、過剰な内部解像度による負荷を抑えます。

```js
const dpr = Math.min(window.devicePixelRatio || 1, 2);
const scaleX = rect.width / CFG.logicWidth;
const scaleY = rect.height / CFG.logicHeight;
ctx.setTransform(dpr * scaleX, 0, 0, dpr * scaleY, 0, 0);
```

Canvasの `width` / `height` は、表示サイズまたはDPRが変わった場合だけ再設定します。
再設定時はCanvasの描画状態がリセットされるため、背景・危険表示のグラデーションキャッシュも破棄します。

## 5. 物理処理

### 5.1 物理スケール

物理値は800px幅を基準にしています。
論理解像度は実行中に変化しないため、スケールは定数として一度だけ算出します。

```js
const WIDTH_SCALE = CFG.logicWidth / 800;
function scaled(v) {
  return v * WIDTH_SCALE;
}
```

現状の `WIDTH_SCALE` は1です。

### 5.2 左右移動

左右加速は接地中だけ適用されます。
入力がない接地中は `friction` を掛け、空中では左右入力による加速を行わず `airDrag` のみを掛けます。

- 接地中加速: `moveAccel = 800`
- 最大横速度: `maxRunSpeed = 220`
- 接地中摩擦: `friction = 0.82`
- 空中抵抗: `airDrag = 0.96`

### 5.3 ホップとダイブ

- ホップ速度: `hopVel = -650`
- ダイブ速度: `diveVel = 520`
- 重力: `gravity = 1800`

接地中のダイブでは `diveIgnore` を0.18秒設定し、直下の足場へ即座に再着地するのを防ぎます。
空中ダイブは1回だけ使用でき、着地すると `airDiveUsed` をリセットします。

### 5.4 着地判定

落下中に、前ステップでは足場の上側にいて、現在ステップで足場上面を通過したかを調べます。
下側から上へ抜けることはできる一方向足場です。

```js
const wasAbove = (prevY + p.hh) <= platTop + 1;
const nowOnOrBelow = (p.y + p.hh) >= platTop;
const withinX =
  p.x + p.hw - CFG.playerHitShrink > pl.x &&
  p.x - p.hw + CFG.playerHitShrink < pl.x + pl.w;
```

## 6. 状態管理とゲームループ

ゲーム状態は `state` で管理します。

| state | 内容 |
|---|---|
| `title` | タイトル。物理更新を行わず、タイトル画面のみ描画 |
| `intro` | 約0.28秒の開始演出。魚を初期足場へ固定し、カメラを少し進める |
| `playing` | 通常プレイ |
| `paused` | 更新停止。現在のゲーム画面へ一時停止UIを重ねる |
| `gameover` | 敵・泡・パーティクルと死亡魚の演出を更新し、ゲームオーバーUIを重ねる |

メインループは `requestAnimationFrame` で動きますが、更新は固定ステップ方式です。

- 固定ステップ: `maxDt = 0.033` 秒（約30.3回/秒）
- アキュムレータ上限: `accumulatorMax = 0.1` 秒
- 1フレームの実時間 `dt` 上限: 0.5秒

通常プレイの更新順:

1. 無敵・開始バナー・ヘルプの各タイマーを更新
2. `updatePhysics(step)`
3. まだ `playing` なら `updateCameraAndScroll(step)`
4. まだ `playing` なら `updateEntities(step)`
5. `playTime` を更新
6. `generateUntil(...)` で先の地形と敵を生成
7. `spawnPowerupIfDue()` で節目の🎧配置を試行
8. `cleanup(cameraY)` で不要オブジェクトを整理

衝突または画面アウトで `gameover` へ移行した場合、同じ固定ステップ内の後続処理をスキップします。

ゲームオーバー中も `updateEntities(step)` は呼ばれます。
ただし、ゲームオーバー時に音符と音符効果を即時削除し、音符による撃破が続かないようにしています。

## 7. プレイヤーと当たり判定

プレイヤーの見た目は30px、物理矩形は34 × 26です。
敵との判定には円形判定を使い、プレイヤー側の半径は次の式です。

```js
Math.max(8, CFG.playerW / 2 - CFG.playerHitShrink)
```

現在値では `17 - 3 = 14px` です。

敵との基本判定:

```js
const pr = playerHitRadius();
const rr = pr + enemy.r;
if (dx * dx + dy * dy < rr * rr) {
  gameOver();
}
```

`pr` は敵ループの外で1度だけ計算します。

開始直後は `startInvulnTime = 0.65` 秒の無敵時間があります。
無敵中は敵との接触判定を行いませんが、🎧は取得できます。

## 8. エンティティ

各エンティティはクラスではなく、ファクトリ関数が返すプレーンオブジェクトで表現します。
敵は `active` フラグを持ち、`active = false` になると更新・衝突・描画の対象外になります。

| 表示 | 種類 | 主な挙動 | 見た目 / 判定 |
|---|---|---|---|
| `🐟` | プレイヤー | 左右移動、ホップ、ダイブ | 30px / 半径14px |
| `🐚` | 貝 | 足場付近に固定。音符では破壊不可 | 30px / 半径14px |
| `🦀` | カニ | 指定された足場範囲を左右に往復 | 30px / 半径14px |
| `🦈` | サメ | 水中を2次元移動し、一定時間ごとに速度を変化 | 30px / 半径14px |
| `🐡` | フグ | 大小を繰り返しながら水中を移動 | 37.5〜60px / 半径17〜28px |
| `🐋` | クジラ | 低速移動＋上下の揺れ。音符に対してHP3 | 108px / 半径52px |
| `🎧` | パワーアップ | 足場上で上下に3px揺れる | 30px / 半径15px |
| `🎵` / `🎶` | 音符 | 魚から全方向へ飛び、一定距離で消える | 22px / 37px、判定半径は共通で12px |

### 8.1 サメ

初速:

- 横速度: 絶対値60〜120
- 縦速度: -20〜20

一定時間ごとに速度を乱数で変化させ、各成分を次の範囲へ制限します。

- 横速度: -140〜140
- 縦速度: -80〜80

画面端では固定余白20pxで反射し、常にカメラ範囲内へ戻します。

### 8.2 クジラ

- 初期横速度: 絶対値24〜48
- 初期縦速度: -8〜8
- 横速度上限: 58
- 縦速度上限: 28
- 上下揺れ: `Math.sin(wh.bob) * 10`
- 画面端余白: 70px（左右）、50px（上下）
- 音符耐久力: 3ヒット

画面外へ流出させず、カメラ範囲内に留め続けるのは仕様です。

### 8.3 フグ

フグは表示深度が100 scrollを超えたあとに生成候補になります。

- 最大スプライトサイズ: 60px（🐟の2倍）
- 最小描画サイズ: 37.5px（🐟の1.25倍）
- 描画スケール: 0.625〜1.0
- 当たり半径: 17〜28px
- 基準速度: 105px/秒
- 実際の生成速度: 基準値の0.8〜1.2倍（84〜126px/秒）
- 膨張位相の進行: 0.9 rad/秒
- 音符1ヒットで消滅

膨張率と当たり半径は同じ正弦波から計算し、見た目と判定を連動させます。
上下左右の画面端で、現在の当たり半径ぶん内側へ戻して反射します。

## 9. 🎧サウンドパワーアップ

### 9.1 出現

次に🎧を出す深度を `nextPowerupDepth` で管理し、初期値は100です。
表示深度がその値へ到達すると、次の条件を満たす足場のうち、魚より下側で最も近いものを探します。

- 足場Yが `player.y + 40` より下
- 足場幅が90px以上

候補があれば足場中央の24px上へ🎧を配置します。
候補がない場合、その100 scrollの節目は配置せずに消化します。

🎧配列には現在ハードコードされた64個の上限があります。

```js
if (target && powerups.length < 64) {
  powerups.push(makePowerup(target.x + target.w / 2, target.y - 24));
}
```

### 9.2 取得と効果時間

魚との円形判定で取得します。
無敵中でも取得可能です。

取得時:

- 取得済み🎧を `active = false` にする
- `musicTimer` を12秒へ設定
- `noteAcc` を0へ戻す
- 取得パーティクルを14個生成

効果中に再取得した場合も、残り時間を12秒へリセットします。

### 9.3 音符の生成

- 放出間隔: 0.09秒
- 1回の放出数: 2個
- `🎵` と `🎶` を交互に生成
- 方向: 全方位ランダム
- 速度: 基準150の0.75〜1.25倍（112.5〜187.5px/秒）
- 魚の中心から放出方向へ6pxずらして生成
- 同時存在上限: 64個

`🎶` は描画サイズが37px、`🎵` は22pxですが、衝突半径はどちらも12pxです。

### 9.4 音符の消滅条件

音符は魚との距離が105pxを超えると消滅します。
距離は生成地点からではなく、毎ステップの現在の魚位置を基準に測定します。
そのため、魚が音符から離れた場合も早く消えます。

### 9.5 敵への効果

音符の判定順:

1. カニ
2. サメ
3. フグ
4. クジラ

| 対象 | 効果 |
|---|---|
| `🦀` | 1ヒットで `active = false` |
| `🦈` | 1ヒットで `active = false` |
| `🐡` | 1ヒットで `active = false` |
| `🐋` | `hp` を1減らし、0以下で `active = false` |
| `🐚` | 音符判定の対象外。音符は消費されずに通過 |

敵に命中した音符は消滅します。

ゲームオーバー時は次を即座に実行します。

```js
player.musicTimer = 0;
player.noteAcc = 0;
notes.length = 0;
```

## 10. 手続き的な足場・敵生成

`generateUntil(targetY)` は、`generatedUntil` が目標Yへ届くまでセグメントを追加します。
通常はカメラ下端より200px先まで生成します。

### 10.1 主足場と追加足場

各セグメントでは、最初に幅の広い主足場を1つ生成します。
コード内では「安全足場」と呼ばれていますが、前の足場からの到達可能性を物理計算で厳密に検証しているわけではありません。
実装上は、比較的広く、敵を置きにくくした主経路候補です。

序盤（`playTime < 3.2`）は足場間隔を82〜118px、主足場幅を230〜320pxにして安全性を上げます。
序盤以降は難度に応じて間隔と幅が変化します。

追加足場は同じ高さ付近で重なりすぎないよう、`platformOverlaps()` と `addPlatformIfClear()` で確認します。

### 10.2 深度帯

```js
const band = Math.floor(depthScroll / 8) % 4;
```

| band | 生成傾向 |
|---:|---|
| 0 | 標準的な配置 |
| 1 | 追加足場が多め |
| 2 | 画面端へ寄せた足場が増える |
| 3 | 足場とサメ・フグが散らばりやすい |

### 10.3 難度プロファイル

難度は0〜1へ制限され、次の要素で構成します。

- `playTime / 150` をsmoothstep化した時間ベースの難度
- `playTime` に基づく正弦波
- 表示深度に基づく正弦波

```js
const t = Math.min(1, playTime / 150);
const smooth = t * t * (3 - 2 * t);
const wave =
  0.08 * Math.sin(playTime * 0.23) +
  0.05 * Math.sin(depthScroll * 0.71);
return Math.max(0, Math.min(1, smooth + wave));
```

`difficultyProfile()` 自体には乱数項はありません。
乱数は、足場位置・敵配置・生成確率の判定で別途使用します。

### 10.4 敵の生成開始

| 対象 | 生成開始条件 |
|---|---|
| `🐚` | `playTime >= 2.0` |
| `🦀` | `playTime >= 2.4` |
| `🦈` | `playTime > 2.8` |
| `🐋` | `playTime > 24` |
| `🐡` | 表示深度 `> 100` |

開始時には、少し先の位置へ貝・カニ・サメを1体ずつ初期配置します。

主足場には貝・カニを置きにくくし、完全に塞がれる確率を下げています。
サメ・クジラ・フグは生成時にプレイヤーとの安全距離を確認します。

## 11. オブジェクト数と整理

### 11.1 生成上限

次のオブジェクトは種類ごとに最大256体です。

- 貝
- カニ
- サメ
- クジラ
- フグ

音符は最大64個、🎧も配列長64未満のときだけ生成します。
足場・泡・パーティクルには同じ256体上限はありません。

### 11.2 in-place整理

`compactEntities()` は新しい配列を作らず、生存要素を前方へ詰めて `length` を短縮します。

```js
function compactEntities(arr, minY, maxY, activeOnly) {
  let write = 0;
  for (let read = 0; read < arr.length; read++) {
    const entity = arr[read];
    if (activeOnly && !entity.active) continue;
    if (entity.y <= minY || entity.y >= maxY) continue;
    arr[write++] = entity;
  }
  arr.length = write;
}
```

足場・貝・🎧・カニは、カメラより上へ200px以上離れると整理されます。
音符は非アクティブになったもの、または広めのカメラ範囲外のものを整理します。

サメ・クジラ・フグは更新処理によってカメラ範囲へ戻されるため、通常はスクロールだけでは消えません。
音符で `active = false` になると整理対象になります。

## 12. 絵文字スプライトキャッシュ

絵文字を毎フレーム `fillText()` と `shadowBlur` で描く代わりに、オフスクリーンCanvasへ一度焼き込み、通常描画では `drawImage()` を使います。

キャッシュ対象:

- `🐟` プレイヤー
- `🐚` 貝
- `🦀` カニ
- `🦈` サメ
- `🐡` フグ
- `🐋` クジラ
- `🎧` パワーアップ
- `🎵` / `🎶` 音符

発光が必要なスプライトは、発光パスと本体パスを生成時にまとめて焼き込みます。

スプライト解像度は、DPRと表示倍率から必要値を計算します。

```js
const need = Math.min(
  4,
  Math.max(1, dpr * (rect.width / CFG.logicWidth))
);
```

必要解像度が現在の `spriteScale` より高くなった場合だけ、0.5刻みに切り上げて再生成します。
表示倍率が下がっただけでは縮小再生成しません。

フグは最大60pxで焼き込み、描画時の `scale` で37.5〜60pxへ変化させます。

5. 🎧
6. カニ

16. 開始バナー

### 13.2 背景と危険グラデーション

背景グラデーションと上部危険グラデーションはキャッシュします。
Canvasの内部バッファを再設定した場合だけキャッシュを破棄します。
危険グラデーションの濃さは `globalAlpha` で調整します。

### 13.3 泡

通常泡は次の場合に描画します。

- タイトル
- ゲームオーバー
- プレイ中に `topDanger > 0`

通常プレイ中で危険状態でない場合は描画しません。
タイトル画面では更新処理を行わないため、表示される泡は静止しています。

### 13.4 パーティクル

パーティクルの種類:

- ホップ時
- 開始時の水しぶき
- ゲームオーバー時の気泡
- 🎧取得時
- 音符による敵への命中・消滅時

更新では全パーティクルを処理しますが、描画時に画面外をスキップします。
現在は配列末尾から `splice()` して寿命切れ要素を削除します。

### 13.5 画面揺れ

ゲームオーバー時のシェイクは、ワールド描画開始前の `ctx.translate()` で適用します。
現在は背景から開始バナー・HUDまでがシェイク対象です。

一時停止UIとゲームオーバーUIは、その後の別 `save()` / `restore()` ブロックで描画するためシェイクしません。

## 14. ゲームオーバー処理

ゲームオーバー時:

1. `state = "gameover"`
2. シェイクと暗転値を設定
3. 音符効果タイマーと音符配列をクリア
4. プレイヤー位置へ `deathFish` を生成
5. 死亡気泡を生成
6. 現在深度が表示上のベスト深度を更新した場合に保存

死亡魚は少し上へ跳ねたあと、回転しながら落下します。
画面下へ90px以上進んだ位置で停止させ、速度値の発散を防ぎます。

ベスト深度は `abyss_best_depth` キーへ、内部値の `maxScroll` を文字列として保存します。
画面表示時は `scrollUnit` で割って整数化します。

## 15. パフォーマンス上の実装

現在の主な最適化:

1. 絵文字をオフスクリーンCanvasへ焼き込んで再利用
2. 背景・危険グラデーションをキャッシュ
3. Canvas内部バッファを必要時だけ再確保
4. `WIDTH_SCALE` を定数として事前計算
5. 共通のプレイヤー衝突半径を敵ループ外で計算
6. `compactEntities()` によるin-place配列整理
7. 泡配列の要素をリセット時に再利用
8. 画面外の足場・敵・パワーアップ・音符・パーティクルを描画時にスキップ
9. 敵を種類ごとに256体、音符を64個へ制限
10. ゲームオーバーへ移行した固定ステップでは後続更新をスキップ

注意点:

- 敵との衝突判定と音符の敵判定は単純な全走査です。
- 特に音符対敵は、音符ごとにカニ・サメ・フグ・クジラの順で走査します。
- 現在の上限（音符64、各敵256）では許容する方針で、空間分割は実装していません。

## 19. 既知の注意点と調整候補

### 現行仕様として把握しておく点

- 入力リスナーはCanvasではなく `window` に登録されている。
- 20秒経過後は `?` キーでヘルプを再表示できない。
- HUDと開始バナーは画面揺れの対象。一時停止・ゲームオーバーUIのみ揺れない。
- ゲームオーバー中も敵・泡・パーティクルは更新される。
- 主足場は安全寄りだが、到達可能性を物理的に保証する探索は行っていない。
- 🎧の配置時に適切な足場がなければ、その100 scroll分はスキップされる。
- 🎧の個数上限64は現在CFGではなく `spawnPowerupIfDue()` 内の固定値。

### 今後の調整候補

- `?` キーで `helpTimer` も復元し、いつでもヘルプを再表示できるようにする
- HUDをシェイク範囲外へ移すか、現状どおりワールドと一緒に揺らすかを明示的に決める
- 🎧の上限を `CFG.maxPowerups` として設定へ移す
- 敵・音符数がさらに増える場合は空間分割やグリッド判定を導入する
- 主足場の到達可能性を、前の足場・ホップ距離・横速度から検証する
- クジラの残りHP表示、深度帯ごとの背景変化、タッチ操作を追加する
